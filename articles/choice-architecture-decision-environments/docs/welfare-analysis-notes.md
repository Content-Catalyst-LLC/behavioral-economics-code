# Welfare Analysis Notes

Choice architecture should not be evaluated only by conversion, uptake, click-through, or option share. A design can change behavior while reducing comprehension, autonomy, or welfare.

## Welfare components

The synthetic workflows define realized welfare as a function of:

- long-run option value
- cognitive cost
- switching cost
- friction cost
- user sensitivity to complexity
- user sensitivity to default and salience
- distributional incidence across user groups

## Welfare accounting

A stylized welfare expression is:

```text
W = long_run_value - cognitive_cost - switching_cost - friction_cost
```

## Key diagnostic

A useful diagnostic is the difference between architecture-adjusted chosen utility and realized welfare. A large gap may signal that the architecture is steering behavior in ways that do not align with long-run user benefit.
